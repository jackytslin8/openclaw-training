🛠️ 實作：Forms API 呼叫

Step 1 — 啟用 Google Forms API

Google Cloud Console → 啟用 forms.googleapis.com：

https://console.developers.google.com/apis/api/forms.googleapis.com/overview?project=526007414074

OAuth scope 需要：https://www.googleapis.com/auth/forms.body（可選）+ drive（共享設定用）

Step 2 — 建立表單（只給 title）

POST https://forms.googleapis.com/v1/forms
Body: { "info": { "title": "六年級社會科 10 分鐘複習小考" } }
建立時只能給 title，description 必須用 batchUpdate 補上（API 會拒絕「Only info.title can be set when creating a form」）。

Step 3 — batchUpdate 三件套：描述 + Quiz + 11 題

POST /v1/forms/{formId}:batchUpdate
{
  "requests": [
    { "updateFormInfo":   { "info": { "description": "..." }, "updateMask": "description" } },
    { "updateSettings":   { "settings": { "quizSettings": { "isQuiz": true } }, "updateMask": "quizSettings.isQuiz" } },
    { "createItem":       { "item": { "title": "請輸入座號", "questionItem": { ... } }, "location": { "index": 0 } } },
    { "createItem":       { "item": { "title": "...", "questionItem": { "question": { "choiceQuestion": {...}, "grading": { "pointValue": 2, "correctAnswers": { "answers": [{"value": "..."}] } } } } }, "location": { "index": 1 } } }
  ]
}

11 題一次送出。選擇題用 choiceQuestion.type: "RADIO"，是非題也用 RADIO（選項 "是" / "否"），grading.correctAnswers 設正解。

Step 4 — moveItem 重排（關鍵！）

坑：createItem.location.index 在多次 createItem 同 batch 內是依序生效，但當所有題目都「插到 index 1」時，後加的會跑到前面，順序會反轉。

解法：用 moveItem 把「當前 index 1」的題目依序搬到正確位置（反轉手法：每次把 index 1 搬到 target index，依序從 10、9、8...2）。

{
  "moveItem": {
    "originalLocation": { "index": 1 },
    "newLocation":      { "index": 10 }
  }
}
欄位陷阱：Forms API 的 MoveItemRequest 欄位是 originalLocation + newLocation（都是 Location 物件含 index），不是 originalItemId + newIndex（那是常見的猜測，會得到「Unknown name "originalItemId" at 'requests[0].move_item'」）。

Step 5 — Drive 公開權限（必做！）

坑：API 建好的表單預設是 私人，只有 owner 看得見。雖然 publishState.isAcceptingResponses = true，但學生點連結會看到「表單已不接受回覆」。

POST https://www.googleapis.com/drive/v3/files/{formId}/permissions
{
  "role": "reader",
  "type": "anyone",
  "allowFileDiscovery": false
}
Forms API 沒辦法直接開公開權限，必須用 Drive API 的 permissions.create 補上「anyone:reader」。

🔗 Step 6 — 連結到試算表（UI 手動 30 秒）

坑：Forms API 沒有設定 linkedSheetId 的端點（v1 和 v1beta 都沒有這個欄位）。即使先用 Sheets API 建好試算表，UI 點「選取現有試算表」時 Google 仍會自動建立新試算表，而不是用 API 建的那個。

  1. 開表單 → 「回覆」分頁
  2. 點 「連結到試算表」（綠色 Google Sheets 圖示）
  3. 選 「選取現有試算表」
  4. 選 API 預先建好的試算表（Google 會自動把它的副本掛上，標題加「(回覆)」）
  5. 完成 → 表單回覆自動寫入試算表
實務上 Google UI 流程會忽略你選的「現有試算表」並建立新檔（標題 = 原表單標題 + "(回覆)"）。先把「孤兒試算表」刪掉是必要的清理動作。最終存回覆的試算表是 Google 自己建的，並不是 API 預先準備的那個。

🧠 5 大教訓（給未來的自己）

Forms API 建立的表單預設是「私人」，必須另外用 Drive API 加 anyone:reader 才能讓學生填。isAcceptingResponses=true 跟 isPublished=true 都無法保證公開。
createItem.location.index 在 batch 內多次使用時，後加的會跑到前面 → 順序反轉。用 moveItem 從「當前 index 1」依序搬到目標 index，是最簡潔的反轉手法。
Forms API 的 MoveItemRequest 欄位是 originalLocation + newLocation，不是 originalItemId + newIndex。要查文件不要憑印象。
Forms API 沒辦法設定「作答時間限制」與「提交後顯示正解」這兩個測驗選項 — 必須從 UI 手動開啟。Grill-Me 階段就應該告知使用者哪些自動化能做、哪些要手動。
Grill-Me 流程的價值：把 13 個隱含決策攤開，避免助手自作主張。例如「作答 3 次」實際上 Forms 只能 1 次或不限制 → 提早說明讓使用者選「表單說明自律」，省下事後改表單的工。
Google 帳號管理：API 操作的帳號（jackytslin0@gmail.com）和瀏覽器登入的帳號（jackytslin8@gmail.com）如果不同，會看不到「回覆」分頁、表單也找不到。解法：用 Drive API 給瀏覽器帳號加 writer 權限，就能跨帳號管理同一份檔案。
